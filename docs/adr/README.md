# Architecture Decision Records

ยังไม่มี ADR ของ repo นี้ จะเพิ่มเมื่อมีการตัดสินใจเชิงสถาปัตยกรรมที่ควรบันทึกไว้ เช่น:

- การเลือก vector store / embedding model (ถ้า Nova ต้องมีของตัวเองแยกจาก Knowledge Studio)
- การออกแบบ `LLMProvider` interface และเหตุผลที่รองรับหลาย provider
- จุดตัดสินใจเรื่อง agent orchestration ในเฟสถัดไป (ดู ROADMAP.md)

ใช้รูปแบบเดียวกับ ADR ใน `CloudForge-Platform-Foundation` repo (ดู ADR-001 ถึง ADR-004 เป็นตัวอย่าง)
